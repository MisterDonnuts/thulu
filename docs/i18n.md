# Internationalization

Every message Thulu produces comes from a catalog: what the dashboard shows,
what the API answers, what the CLI prints, what the daemon writes into a task,
what it logs and what its errors say. Code names a key; the catalog holds the
words, in English and in Spanish.

Two catalogs, one convention:

| | Daemon, CLI, API (Go) | Dashboard (Astro) |
|---|---|---|
| Files | `internal/i18n/locales/<locale>/**/*.json` | `web/src/i18n/locales/<locale>/**/*.json` |
| Render | `i18n.T`, `i18n.TCtx`, `i18n.Text`, `i18n.Log` | `t()` from `src/i18n` |
| Errors | `internal/apperr` | the API's `{error, code}` |
| Guard | `internal/i18n/guard_test.go` (`make test`) | `web/scripts/i18n-guard.test.mjs` (`make test-web`) |

The MCP servers in `tools/` follow the same convention with a catalog each; see
[MCP servers](#mcp-servers). So do the shell scripts an operator runs and the
ones that start an agent; see [Shell scripts](#shell-scripts).

English (`en`) is the source catalog. Spanish (`es`) has exactly the same keys
and the same variables. Spanish is rioplatense with voseo: "Volvé a mencionarlo", "si querés".

## Keys

A file is a namespace and its nested objects are groups:
`locales/en/task.json` with `{"errors": {"not_found": "…"}}` defines
`task.errors.not_found`. A file in a subdirectory adds to the namespace:
`locales/en/api/tasks.json` holds `api.tasks.*`.

- The namespace is the Go package (`task`, `webhook`, `cli`) or the dashboard
  page or module (`tasks`, `settings`, `lib.webhooks`). A large package splits
  by area into a directory: `api/tasks.json`, `api/projects.json`.
- Groups say what kind of text it is: `errors`, `log`, `comments` (written into
  a task), `prompts` (sent to an agent), `cli` (printed), `labels`, `hints`,
  `buttons`, `toasts`, `empty`, `confirm`. Pick the one that matches; add a new
  one only when none does.
- Leaf names say what happened, in snake_case: `endpoint_not_found`,
  `create_failed`, `moved_to_stage`. Not `error1`, not the English sentence.
- One key per message. The same words in two places with two meanings are two
  keys; the same message reused is one key.
- The dashboard's shared words live in `common`: `common.buttons.*` (Cancel,
  Save, Delete, Close…), `common.status.*` (Loading…, Saving…) and
  `common.kbd.*` (the shortcut help). A page names its own key only when its
  wording differs, as in `chat.confirm.delete_ok` ("Borrar") or
  `tasks.kbd.focus_search` ("Ir al buscador").
- Keys are string literals at the call site, so the guard can check them. A key
  chosen at runtime lives in a table of literals (`map[Status]string{…}`).

## Messages

- Variables are named in braces: `"moved {task} to {stage}"`. Never positional
  `%s`. Go may add a fmt verb, `{cost:%.2f}`, `{name:%q}`; the dashboard formats
  numbers and dates with `Intl` before passing them.
- Counts are plural objects, chosen by `count`:
  `{"one": "{count} task", "other": "{count} tasks"}`.
- Markdown and line breaks stay in the message (`\n`, `**bold**`), since they
  are part of what the reader sees.
- Proper names that are not translated (GitHub, Kubernetes, OIDC) still go
  through the catalog when they are a label on screen.

## Go

```go
// Errors: a key, the kind of failure, the values.
return apperr.NotFound("task.errors.not_found", "id", id)
return apperr.Invalid("api.tasks.errors.title_required")
return apperr.Wrap(err, "task.errors.load_failed", "id", id)

// Sentinels keep their names and still work with errors.Is.
var ErrNotFound error = apperr.NotFound("task.errors.not_found")

// HTTP: the message in the caller's language, plus the key as "code".
writeError(w, r, http.StatusConflict, err)      // status 0 = from err's kind
writeErrKey(w, r, http.StatusBadRequest, "api.tasks.errors.title_required")

// Logs: always the source locale, so operators can grep them.
log.Printf("[task] %s", i18n.Log("task.log.reap_failed", "id", id, "err", err))
logx.Warn(f.Close(), "task.log.close_failed", "path", p)

// Text the daemon writes for people to read later (task comments, CLI output,
// agent prompts): the daemon's locale, OCTOPUS_LOCALE.
body := i18n.Text("task.comments.auto_advanced", "stage", st.Label)

// Inside a request handler, anything answered to the caller: its locale.
msg := i18n.TCtx(r.Context(), "api.tasks.hints.blocked", "n", n)
```

Which locale is which:

- request (`TCtx`, `writeError`): the dashboard's `octopus_locale` cookie, else
  `Accept-Language`, else the daemon's;
- daemon (`Text`, `apperr.Text`): `OCTOPUS_LOCALE`; for CLI commands, the
  terminal's `LC_ALL`/`LC_MESSAGES`/`LANG` when `OCTOPUS_LOCALE` is unset;
- source (`Log`, `err.Error()`): always English.

`apperr.Kind` maps to the HTTP status: `Invalid` 400, `Unauthenticated` 401,
`Forbidden` 403, `NotFound` 404, `Conflict` 409, `Precondition` 412,
`TooLarge` 413, `Unprocessable` 422, `RateLimited` 429, `Internal` 500,
`NotImplemented` 501, `Unavailable` 503, `Timeout` 504. `Wrap` keeps the kind
of what it wraps; `WrapKind` sets one.

A wrapping message ends in its cause, like `%w`. When
the cause belongs elsewhere in the sentence, the message places it with
`{cause}`: `"{cause} (while reading {path})"`.

An error from outside Thulu (the standard library, a driver, Docker) keeps
its own text; it reaches the reader as data at the end of the chain.

## Dashboard

```astro
---
import { t } from "../i18n";
---
<PageHead title={t("dashboard.title")} subtitle={t("dashboard.subtitle")} />
<button aria-label={t("dashboard.buttons.shortcuts")}>{t("dashboard.buttons.open_board")}</button>

<script>
  import { t } from "../i18n";
  toast(t("tasks.toasts.renamed"), "ok");
  el.textContent = t("tasks.drawer.uploading", { file: filename });
</script>
```

A sentence that holds markup (a command in `<code>`, a link) renders with
`tParts`: the markup's place is a variable passed as `SLOT`, and the page
writes the element between the parts it gets back. Catalog text never goes
through `set:html`.

```astro
---
import { SLOT, tParts } from "../i18n";
const sub = tParts("sandboxes.subtitle", { cmd: SLOT }); // text, "cmd", text
---
<p>{sub.map((p, i) => (i % 2 ? <code>{CMD}</code> : p))}</p>
```

Each locale is its own build (`npm run build` runs `scripts/build-locales.mjs`):
`en` into `dist/`, the others into `dist/_locales/<locale>/`, sharing
`dist/_astro/`. The daemon serves a page from the directory of the request's
locale. Settings has the language picker, which sets the cookie.

## MCP servers

Each server under `tools/` has its own catalog, `locales/en.json` and
`locales/es.json`, and the helper `i18n.js`: `t(key, params)` renders in
`OCTOPUS_LOCALE`, `tLog(key, params)` in English for logs.

```js
import { t, tLog } from "./i18n.js";

server.tool("task_get", t("tools.task_get.description"), {
  id: z.string().describe(t("tools.task_get.params.id")),
}, …);
throw new Error(t("errors.no_key"));
console.error(tLog("log.sse_closed", { session }));
```

Groups: `tools.<tool>.description`, `tools.<tool>.params.<param>`, `errors`,
`log`, `text` (other text a tool returns), `labels`.

A server's Docker build sees only its own directory, so every server carries an
identical copy of `i18n.js`; `tools/octopus-api/i18n.js` is the original. Each
Dockerfile copies `i18n.js` and `locales/`, and `tools/docker-compose.yml`
mounts them next to `server.js`.

## Shell scripts

The installer, the operator scripts (`scripts/setup-auth.sh`,
`scripts/*-observability-credential.sh`, `deploy/backup.sh`,
`deploy/k8s-data-plane/render.sh`) and the agent container's scripts
(`images/entrypoint-base.sh`, `images/kube-agent-entrypoint.sh`,
`images/snippets/`) share one catalog: `internal/i18n/shell/locales/<locale>/`.
The file name is the namespace (`install.json` → `install.…`); a leaf is a
string or a plural object (`{"one": …, "other": …}`); variables are `{name}`.

A script cannot import a Go package, so each one carries a generated block
between `# BEGIN i18n` and `# END i18n` that defines two functions:

```sh
msg install.errors.required tool curl        # the reader's language
msg_en agent.log.ca_trusted bundle "$file"   # always English
msg backup.cli.pruned count "$n" keep "$k"   # count picks the plural form
```

The block holds only the namespaces its scripts use, and is POSIX `sh`, so
`install.sh` stays runnable with `curl … | sh`. The agent scripts share one
block in `images/snippets/i18n.sh`, which every entry point sources first.

Which language:

- An operator script reads `OCTOPUS_LOCALE`, else the terminal's (`LC_ALL`,
  `LC_MESSAGES`, `LANG`).
- An agent container reads `OCTOPUS_LOCALE`. A run somebody asked for over
  HTTP gets the language of that request: a mention run, the comment's; a
  chat container, the turn's that started it; an evidence batch, the one of
  whoever queued it (stored on the batch). Everything else (stage runs,
  schedules, CI hooks) gets the daemon's. Text the agent reads (its prompt,
  the brief, the run context) goes through `msg`; the container log goes
  through `msg_en`, like the daemon's own log. `mcp-config.sh` passes the
  same locale to the MCP servers as `?locale=`, so what thulu-browser burns
  into a video follows it.
- Text that outlives the run outside Thulu (a commit message, an IAM role's
  description) goes through `msg_en`.

Log tags (`ERROR:`, `WARN:`, `==>`, `[task-brief]`) stay in the code.

After editing the catalog or adding a call, regenerate the blocks:
`go test ./internal/i18n/shell -update`. Without the flag the test is the
guard: it fails on a stale block, a key the catalog lacks, a call whose
variables do not match, a key no script names, a locale missing a key, and
words outside the catalog. Mark a literal that is not a message (embedded
JavaScript, a JSON body, a directory list) with `# i18n-ignore <reason>` on its
line or the line above.

## The guards

Both guards fail the build on: a key the catalog lacks, a call whose variables
do not match its message, a catalog key no code names, a locale missing a key
or a variable, and text that reads as words outside the catalog.

To see one area's problems: `I18N_GUARD_PATH=internal/task go test
./internal/i18n -run TestCatalogGuard`, or `I18N_GUARD_PATH=pages/tasks npx
vitest run scripts/i18n-guard.test.mjs` in `web/`. The MCP servers' guard is
`web/scripts/i18n-tools-guard.test.mjs` (`I18N_GUARD_PATH=octopus-api`); it also
checks that every `i18n.js` copy matches the original and that each Dockerfile
packages the catalog. The dashboard and MCP guards share their checks
(`web/scripts/i18n-scan.mjs`).

A string that is words but not a message (a shell command, an HTTP header
value, a CSS font stack, a regex sample) gets `i18n:ignore` (Go) or
`i18n-ignore` (dashboard) in a comment on its line or the line above, with the
reason: `//i18n:ignore shell command, not a message`.

## What is not in the catalog

- Identifiers: JSON field names, enum values, event names, CSS classes, SQL,
  environment variable names, URLs.
- The catalog loader's own errors (`internal/i18n`), raised when the catalog
  itself cannot be read.
- Test files.
- Files that are content rather than code: `docs/`, skill
  prompts under `internal/builtin/`, Helm `NOTES.txt`.
- Developer-only scripts (`scripts/compat.sh`, `scripts/k8s-dev.sh`,
  `scripts/dev-version.sh`)
  and the project starter under `internal/api/scaffold/`, which becomes the
  user's own code.
